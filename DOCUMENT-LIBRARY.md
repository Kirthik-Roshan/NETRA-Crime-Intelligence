# Document Chat And Saved Reports

In the Assistant, attach a PDF, PNG, JPEG or WebP with the paperclip control.
Catalyst Zia OCR extracts its text server-side. The original file and extracted
text are saved to the signed-in officer's library. Attach up to three files;
the upload limit is 8 MB per file.

Questions and follow-ups retrieve numbered passages from the attached files.
Catalyst QuickML generates an answer from those passages, and each returned
supporting quote is checked against the stored text. If QuickML is unavailable
or returns invalid citations, NETRA returns actual retrieved excerpts. It does
not substitute a search of the crime database for an attached-document answer.
Greetings retain the normal conversational path.

OCR passages are not PDF page numbers. OCR cannot interpret photographs or
diagrams beyond their text. Uploaded claims remain document statements rather
than verified FIR facts. Extraction accuracy still needs checking against the
original. The text analysis limit is 120,000 characters per file; retrieval
consults up to six 1,600-character passages and reports its coverage. Very long
documents should be narrowed or split for targeted questions.

## Portal Library

The Reports page now has **Report builder**, **Saved reports** and **Documents**
views. Files can be searched, previewed and downloaded. **Chat about this file**
opens the Assistant with the chosen file attached. The Assistant also has a
document picker for previously uploaded files.

New Assistant, report-builder, evidence-chat and investigation-brief exports are indexed
automatically before delivery. Print previews and conversion fallbacks are retained as
labelled printable reports. Archive failures block delivery and show a retryable error.
Reports archived by older
revisions were not indexed per officer and are not automatically exposed by
this library. Re-export a report to add it.

## Catalyst Storage

- By default, originals, extracted text and private library metadata use the
  existing `STRATUS_BUCKET` (`ksp-netra` by default).
- To store originals in **Catalyst FileStore**, create a private folder in the
  Catalyst console and set `NETRA_FILESTORE_FOLDER_ID` on the Function. Folder
  creation must be handled through the console for Production. Configure the
  folder in each environment; do not assume IDs are interchangeable.
- The server credential must be able to upload/download in that folder. Do not
  grant direct public or broad end-user access to the folder or Stratus bucket;
  the Function checks officer ownership before returning file contents.
- FileStore holds the original binaries when configured. Stratus remains
  required for the officer-specific index and OCR text.
- No new Data Store tables or changes to the 28-table crime schema are needed.
- PDFs are generated by SmartBrowz. Document recognition uses Zia OCR; answer
  generation uses the existing QuickML LLM credentials.

Official references:

- [Zia OCR input formats](https://docs.catalyst.zoho.com/en/zia-services/help/optical-character-recognition/key-concepts/)
- [FileStore upload API](https://docs.catalyst.zoho.com/en/sdk/nodejs/v2/cloud-scale/file-store/upload-file/)

## Verification

```bash
npm run documents:test
NETRA_PLAYWRIGHT_MODULE=/path/to/playwright node scripts/test-document-library-ui.cjs
npm run release:gate
```

The browser test requires the local server (default port 3002), uses the real
Function handler with simulated Zia/FileStore/Stratus services, and renders
PDFs using local Chromium. Live OCR, QuickML, FileStore folder permissions and
SmartBrowz must be checked after deploying matching Function/Web Client
revisions. Upload a readable sample PDF and image, ask a follow-up, export a
conversation, reopen it through Saved reports and download it under the same
signed-in officer.
